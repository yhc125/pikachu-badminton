# Rollout v1 vs. the heuristic incumbent

Run with Node v26.5.0. The case manifest is deterministically generated by
`challenge` with this exact seed and token (use a new directory to rerun):

```sh
node tools/ai-arena/lab.mjs challenge --dir=.ai-lab/rollout --token=rollout-v1 --seed=752871 --cases=5 --jobs=6 --max-ticks=4800
```

| Result | Heuristic incumbent | Rollout challenger |
| --- | ---: | ---: |
| Wins / 16 | 3 | 14 |
| Losses | 2 | 0 |
| Timeouts | 11 | 2 |
| Zap fires / hits | 0 / 0 | 3 / 3 |

The mixed suite includes stock CPUs and parameterized opponents. It is a small
fixed evaluation, not a population win-rate estimate. In the separate direct
matchup against the incumbent, the challenger won both times it served first
(11–0 both times). With the incumbent serving first, both games timed out
at 0–0. The challenger therefore **did not pass the promotion gate** and did
not replace the incumbent. The 3 zap hits are observations, not rewards;
lookahead may still choose to recover instead. Every partial score in a
match marked `timeout` is excluded from the win count.
